# キャンペーン画像表示ポリシー

この文書は、ランキング、結論、詳細に表示する公式キャンペーン画像の恒久ルールです。機械可読な正本は`data/campaigns/presentation-policy.json`で、現在のポリシーIDは`campaign-image-v1`です。

## 表示ルール

| 場所 | PC | SP | 画像の収まり方 |
| --- | --- | --- | --- |
| ランキング | 96×96px | 84×84px | 正方形枠へ`contain` |
| 結論 | 記事幅100%、横長画像の自然比率 | SP向け画像を幅100%、自然比率 | 切り抜かない |
| 詳細 | 記事幅100%、横長画像の自然比率 | SP向け画像を幅100%、自然比率 | 切り抜かない |

SPへの切替は860px以下です。PC用公式画像の縦横比が1.5以上なら`natural`、それ未満なら16:9の白背景枠へ`contain`する`contain-16x9`を使います。横長画像が見つからないことだけを理由に掲載中キャンペーンを非公開にはしません。

## 画像選定順

PC編集画像は、手動指定された公式画像、公式詳細ページのPC用KV、公式一覧バナー、公式OG画像の順で探します。SP編集画像は、公式SP用KV、現在利用中のSP画像、公式一覧画像の順です。ランキング画像はSP編集画像と同じ公式素材を再利用でき、CSSの正方形枠で表示します。同じ公式ファイルを複数用途で使う場合は複製せず、同じ保存パスを参照します。

新規キャンペーンで公式画像を一つも取得できない場合は`pending`として非掲載にします。既存キャンペーンの再取得に失敗した場合は直前の画像を維持し、Slackへ警告します。既存の16:9代替表示は毎日通知せず、新たに代替表示へ移行した場合または取得元が変わった場合だけ通知します。

## 自動検証

`npm run check:assets`は、ポリシー版、用途別画像、公式取得元、マニフェスト寸法と実寸、横長判定、代替表示、孤立画像を検査します。`npm test`はbuildと既存回帰テストに加えて、Playwrightで1440pxと390pxの実ページを検査し、ランキング・結論・詳細の6つの固定基準画像を比較します。

日次GitHub Actionsが変更できるのは、生成JSON、アーカイブ、`images.json`、保存済み公式画像だけです。CSS、コンポーネント、このポリシー、テスト、文書に差分が生じた場合は、Artifact保存、mainへのcommit、Cloudflare公開より前に停止します。画像比較の差分は失敗時だけ7日間Artifactへ保存されます。画像検証はOpenAI／Anthropic APIを呼びません。

## 意図的にデザインを変更する場合

1. 最新の`main`から作業ブランチを作ります。
2. ユーザーの明示承認を得ます。
3. `presentation-policy.json`のIDを新しい版へ変更します。
4. UI、CSS、画像同期、構造テスト、Playwright基準画像、本書を同じPull Requestで更新します。
5. `npx playwright install chromium`、`npm run check:assets`、`npm run lint`、`npm test`を実行します。
6. PC 1440pxとSP 390pxを目視し、Pull Requestでレビューしてからmergeします。

日次処理中に基準画像を自動更新したり、テストを通すためだけに許容差を広げたりしてはいけません。
